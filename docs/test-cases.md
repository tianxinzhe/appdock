# AppDock（MostUsed Widget）— 全量测试用例

> 版本：V1.0（对应 versionCode 1 / versionName 1.0.0）
> 包名：`com.soulscop.mostusedwidget`｜应用名：AppDock
> 用途：交付测试人员执行的手工测试用例集，覆盖功能、数据、异常、合规、兼容性。

---

## 1. 测试目标与范围

**测试目标**：验证 AppDock MVP 在所有承诺功能上可用、数据准确、无崩溃、无隐私合规风险。

**范围内**：

| 模块 | 覆盖内容 |
| --- | --- |
| 权限 | 使用情况访问权限的引导、检测、撤销、恢复 |
| 榜单 | 热度统计展示、刷新、空态、隐藏、置顶 |
| 设置 | 排序模式、权重、衰减、批量过滤、黑名单、自动刷新、导出、清数据 |
| 内购 | 本地桩购买、恢复、状态持久化、高级功能解锁 |
| 小组件 | 添加/取消/配置/渲染/点击启动/刷新/占位/多实例/尺寸 |
| 隐私 | 隐私政策页、无网络上报、权限最小化 |
| 非功能 | 弱网、旋转、深色模式、大字体、耗电、兼容性 |

**范围外（不要当缺陷提）**：真实支付扣费、云端同步、桌面图标自动整理/排序、鸿蒙系统、多语言切换（本期中文单语）。

### 2.3 测试数据准备（关键，否则大量用例无法执行）

1. 设备上预装 **8 个以上** 第三方应用（含 1 个游戏），并各有真实打开记录。
2. 测试前 30 分钟内 **依次打开 5~6 个应用**，每个停留 1~2 分钟，形成可观测的 7 天/30 天数据。
3. 留 1 台「干净」设备或先执行 `adb shell pm clear com.soulscop.mostusedwidget` 用于空态验证。
4. 建议同时打开系统「数字健康 / 使用情况访问」页面，作为统计结果对照基准。

## 3. 用例书写约定

- **编号**：`模块前缀-两位序号`，如 `B-03`。
- **优先级**：`P0` 阻塞发布（必过）；`P1` 主要功能；`P2` 次要/体验/兼容。
- **执行结果**：`通过` / `失败` / `阻塞`，失败必须附截图与日志（`adb logcat -s AndroidRuntime`）。
- **判定原则**：只有「预期结果」全部满足才算通过；文案错别字按 P2 提缺陷。

## 4. 已知实现行为（避免误报）

以下为当前版本的**设计内行为**，测试时按此判断，不要当缺陷提交（如认为不合理请提「产品建议」而非 Bug）：

1. **内购是本地桩**：点击购买约 0.4 秒后直接解锁，无真实支付、无扣费、无商店页面。
2. **恢复购买只读本地状态**：未购买时点击无任何反馈（无 Toast、无提示），购买后按钮消失。
3. **免费版小组件最多 4 个图标**，即使数据库里配置为 6/8 也只渲染 4 个。
4. **清除统计数据只删热度缓存**（榜单/小组件数据），不影响黑名单、设置项、高级版状态；刷新后会重新生成。
5. **设置项修改后约 600ms 才重新计算**并刷新小组件，不是即时生效。
6. **免费版排序固定为「近 7 天启动次数 × 2」**；排序模式、权重、衰减因子仅高级版生效。
7. **小组件不自动刷新**（`updatePeriodMillis=0`），仅在以下时机更新：添加小组件、点小组件「刷新」、主界面点刷新、设置变更、购买解锁、首次授权成功、高级版每日定时任务。
8. **添加小组件时点「取消」不会把小组件放到桌面**。
9. **榜单列表行本身不可点击**，只能通过右侧「⋮」菜单操作。
10. **游戏识别**在 Android 8+ 依赖应用商店分类（category=GAME），侧载游戏可能识别不到。
11. **每日自动刷新**为 24 小时周期任务，实际触发时间受系统省电策略影响，可能延后。

| 缺陷标题 | 【模块】一句话描述现象 |

| 严重程度 | 致命（崩溃/数据丢失/合规风险）/ 严重（主功能不可用）/ 一般 / 轻微（文案/样式） |

| 预期结果 | 引用的用例预期 |
| 复现率 | 必现 / 偶现（x/10） |
| 日志 | `adb logcat -s AndroidRuntime` 片段 |

**严重程度判定基准**

- 致命：崩溃、白屏、权限流程卡死、CSV 数据错误、对外上报数据、购买后高级功能不生效。
- 严重：榜单数据明显错误、小组件点击不启动、隐藏/置顶失效、清数据后无法恢复。
- 一般：设置项不持久化、占位文案缺失、多实例配置串号。
- 轻微：文案措辞、间距、颜色偏差等体验问题。

## 8. 通过标准

1. **P0 用例 100% 通过**；P1 通过率 ≥ 95%；P2 通过率 ≥ 85%。
2. 无「致命」「严重」级别未修复缺陷。
3. 核心链路（授权 → 榜单 → 小组件 → 购买 → 高级功能）在 D1/D2 设备上连续跑 3 轮无异常。
4. 无崩溃日志（`AndroidRuntime` / `FATAL`）。
5. 合规检查（L-04~L-07）全部通过。
